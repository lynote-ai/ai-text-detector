# Demo data

[Chinese](README.zh-CN.md)

Only `demos/` is published. It contains five files across three pipeline
stages: 25 synthetic JSONL records (20 train + 5 validation) plus two JSON
artifacts (a calibration result and one full detect-response envelope). Every
record is authored for this repository and carries the provenance key
`"source": "synthetic"` — real user text from a detection-service log never
writes that field, so it can never pass `make demo-validate`.

`data/demos/manifest.yaml` pins the selection policy, per-file record counts,
and SHA-256 digests. The full training/validation datasets are intentionally
excluded from this repository: they are derived from user-supplied log exports
that may contain personal data.

## Schemas

- `01_prepare/train_hier_demo.jsonl` and `01_prepare/val_hier_demo.jsonl`:
  two-level soft-label records (`scan_id`, `text`, `doc_label`,
  `sentences[].{text, y_origin, y_human_ai}`, `gptzero_doc_class`,
  `gptzero_language`), plus the demo-only `source` key. Every `scan_id` in the
  train file satisfies `md5(scan_id)[:8] % 10 != 1`; every one in the val file
  satisfies `== 1`. Languages: en / zh / es / pt, with `human`, `ai`, and
  `mixed` documents included.
- `02_calibrate/calibration_demo.json`: exactly the artifact written by
  `code/k_calibrate_hier_model.py` — `temperature`, `doc_class_names`,
  `fitted_samples`.
- `03_serve/detect_response_demo.json`: the full `{code, msg, data}` envelope
  for one document, self-consistent with the service constants
  (`V2-hier-1` / `V2h`, the 0.33/0.6/0.8 bands, the neutral result-message
  templates, paragraph means, highlight rules).

The record schema and its provenance are described in
[../docs/DATA_CONSTRUCTION.md](../docs/DATA_CONSTRUCTION.md).

## Release guard

```bash
make demo-validate
```

The guard fails if: a record is missing the `source: synthetic` provenance key,
a `scan_id` violates its file's split rule, a probability vector does not sum
to 1, a sentence is not a substring of its document, a file's record count or
SHA-256 drifts from the manifest, or any file appears under `data/demos/`
that is not registered. The manifest itself is regenerated by the
maintainer-only `make demo-refresh`.

## Why two stages have no demo file

Stages `j_train_hier_model` (training) and `l_eval_hier_model` (evaluation)
produce model weights and run-specific reports. Neither is a bounded, reusable
data artifact, so neither ships a demo file; this is stated in
`manifest.yaml` notes as well.

## Before publishing

The automated guard bounds volume and checks integrity only. If you
redistribute these files under your own name, a human must still review all
25 records for licensing and provenance — the gate is not a substitute for
judgment.
